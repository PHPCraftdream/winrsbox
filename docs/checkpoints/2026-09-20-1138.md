## Session summary

Долгая сессия по `winrsbox` (D:\dev\rust\winrsbox) — Windows-песочнице на CoW-оверлее с
ntdll-хуками. Началась с того, что `winrsbox cx` падал с `CreateProcessW failed …
0x80070002`, и закончилась крупным рефакторингом раскладки исходников, который сейчас
идёт в пяти git worktree.

**Первая половина — починка.** `cx`/`cy` не запускались, потому что `CreateProcessW`
дописывает к голому имени только `.exe` и не раскрывает `PATHEXT`. Решено через
`SearchPathW` — тот же поиск, который использует сам `CreateProcessW`; добавился ровно
перебор расширений. Одна подстановка починила и пять потребителей `target_args[0]`,
включая `wfp::app_id_from_path`: для любой цели с голым именем фильтры RFC1918 молча не
ставились (измерено: 3 отказа до, 0 после).

Попутно вскрылось, что закоммиченный накануне хардненинг сломал четыре базовых пути:
CoW не работал вообще (корни оверлея не сворачивались по регистру), пайпы/консоль/сокеты
отвергались, `--guard static` не запускал ничего (hook.dll убивал себя на своих же
RWX-трамплинах), и все цели гибли на выходе с `0xC0000005`. Каждое подтверждено
сравнением со сборкой от 18.09, а не рассуждением.

**Корневая причина того, что это прошло мимо 1328 зелёных тестов, оказалась двойной:**
интеграционные тесты предпочитали устаревшие release-артефакты, И `cargo test` вообще не
обновляет `target/<profile>/winrsbox.exe` (собирает bin как тестовую обвязку в `deps/`).
Оба закрыты; проверка тут же поймала меня самого.

**Дальше по просьбам пользователя:** консольная диагностика стала опциональной (`-v`),
сетевой контроль — выключен по умолчанию (`network: guarded` в ktav включает), и
починен DNS: `dnsapi` читает список серверов из `…\Services\Tcpip\Parameters` через
`RegCreateKeyEx(KEY_READ)`, а весь куст `Services` в запрете как вектор персистентности.
Решено третьим путём — `CreateKeyAction::OpenExistingOnly`: такой вызов уходит в
`NtOpenKey`, существующий ключ открывается, создать нельзя ничего.

Последним починен `WARNING: failed to clean up stale arg0 temp dirs: Access is denied` у
codex — `resolve_for_hook` отбрасывал открытие с пустым `ObjectName`, хотя вместе с
`RootDirectory` оно указывает на сам каталог-родитель; это форма, которую использует
`remove_dir_all` в Rust.

## Decisions

- Сеть по умолчанию НЕ перехватывается: без `network: guarded` не открывается WFP-движок
  и не ставится детур `connect`. Причина — трафик и так идёт от приложения (хук никогда
  не проксировал), а песочницу выдавали только записи `winrsbox-block-*` в таблице
  фильтров. Осознанное ослабление, задокументировано первым абзацем в SECURITY.md.
- `--block-localhost` и любое `netrule` включают контроль неявно — иначе правило висит
  бездействующим, а человек видит его в `netrule list` и считает работающим.
- Консольная диагностика развязана с уровнем файлового лога: `log_level: trace` даёт
  полный аудит на диске при молчащем терминале. Гейт ставился только там, где то же
  самое уже пишется в JSONL.
- `layout-guard` НЕ вливается до конца рефакторинга: тест красный по замыслу.
- Правило «≤7 элементов» к корню репозитория не применяется (решение пользователя:
  «в основном для исходников, без фанатизма»); `repro/` оставлен на месте, потому что на
  него ссылаются документы прошлых расследований.
- Параллельных агентов — не больше двух. Четыре исчерпали квоту провайдера.

## Lessons worth carrying forward

- Структурный тест, который ищет в исходнике литерал, содержит этот же литерал сам.
  Склейка всех файлов модуля заставила два пина найти самих себя и упасть. Теперь
  `module_source` исключает тест-модули по объявлениям `#[cfg(test)] mod` в `mod.rs`.
- `include_str!` после переноса кода — тихо-зелёный тест. В этот раз повезло: пути
  сломались на этапе компиляции. Полагаться на такое везение нельзя.
- `cargo test` НЕ обновляет `target/<profile>/winrsbox.exe`. Интеграционные тесты
  требуют отдельного `cargo build --workspace` тем же профилем.
- Не править исходники, пока идёт фоновый интеграционный прогон: проверка устаревания
  честно уронит его.
- `grep -v "0 passed"` съедает строки вида «35**0 passed**»; `head` внутри фоновой
  команды обрезает вывод до того, как дойдут настоящие наборы. Дважды сделал из этого
  неверный вывод.
