## Lessons worth carrying forward

- Worktree, созданный ДО split файла по layout-guard, при мёрже своих правок
  обратно нужно вручную развести по новым под-файлам через SAME/DIFF-сверку
  каждого затронутого файла — паттерн повторился дважды в этой сессии (S06
  после сплита detours.rs/tests.rs).
- Частичное банковение задачи оправдано: если одна часть многосоставной
  задачи полностью готова и изолированно проверяема (другой крейт, другой
  файл), а другая часть сломана/недоделана — слить готовую часть отдельно,
  не ждать всю задачу целиком и не терять верифицированную работу.
- Восстановление прерванной правки через сохранённый `diff`/`patch` — риск:
  ханки внутри одной функции могут не пересечься чисто, и middle-of-function
  контент теряется молча (`patch` репортит только явный FAILED hunk, не
  скрытую потерю контента внутри успешно применённых ханков). Не доверять
  такой реконструкции без полной ре-верификации; при сомнении — переописать
  задачу агенту заново с архитектурными подсказками вместо мёржа сырого
  восстановления.
- Heredoc (`<< 'EOF'`) для передачи длинных промптов в `rush run` — хрупок
  при большом количестве апострофов/кавычек в тексте промпта, ломается
  непредсказуемо ("unexpected EOF while looking for matching `'`" на
  случайной строке). Передавать промпт через временный файл (`Write` +
  `rush run < file.txt`) устраняет весь класс проблемы — использовать это
  как стандартный способ впредь.
- `cd` в Bash-инструменте этой сессии не всегда персистентен между вызовами
  (наблюдалось многократно) — всегда использовать абсолютные пути или явный
  `cd` в начале каждой команды, не полагаться на память состояния оболочки.
