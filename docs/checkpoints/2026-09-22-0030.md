## Decisions

- Рефакторинг раскладки закоммичен (`bedcc3f`) явным разрешением пользователя —
  до этого 230+ путей копились некоммиченными несколько ходов.
- Правки по ревью **не коммитятся** — лежат в primary некоммиченными до явной
  просьбы, как и весь сентябрь этой сессии.
- Стратегия волны 2 — пары по 2 без пересечения файлов, не полный fan-out:
  явно объяснено пользователю с обоснованием (плотность конфликтов по горячим
  файлам + cp-based слияние + установленный лимit агентов).
- npm-пин переведён на `e491803` (не на локальные `bedcc3f`/`dd97183`, которые не
  запушены и пином быть не могут).
- Worktree-агентам для больших находок (S02) даётся честное указание
  триажировать по приоритету, если весь объём не влезает в дедлайн, вместо
  требования сделать всё поверхностно.
- Разница между «созданный от HEAD worktree» и «primary с некоммиченными
  правками» теперь всегда явно проверяется (`diff` по каждому файлу, который
  заденет новая задача) и досеивается ПОЛНЫМ поддеревом, не поштучно.

## Lessons worth carrying forward

- Worktree от `HEAD` не видит некоммиченные правки primary — если новая задача
  трогает файл, уже правленный предыдущей задачей этой же волны, обязательно
  сверять `diff` по каждому такому файлу и досеивать ПОЛНЫМ поддеревом
  (`cp -r` всей `src/`), не выборочно — поштучный выбор один раз уже пропустил
  2 из 6 файлов.
- После `cp`-восстановления файла в рамках негативного доказательства теста —
  `touch` перед перезапуском тестов; mtime после `cp` иногда не продвигается
  достаточно для инкрементального cargo-кэша, что дважды давало ложный красный
  результат.
- `cargo test/build --workspace` НЕ собирает bench-цели — молчаливый регресс в
  них переживёт любое число зелёных прогонов основного набора.
- При плотной сетке пересечений файлов между задачами полный параллельный
  fan-out — не автоматический выбор просто потому что доступен `/wrush`;
  считать конфликты явно перед запуском батчей.
