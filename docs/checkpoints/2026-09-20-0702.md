## Decisions

- Worktree засевается **рабочим деревом**, а не HEAD: вся работа некоммичена, иначе агенты правят устаревшую базу.
- Параллелизм ограничен 2–5 прогонами с непересекающимися файлами; после трёх сбоев провайдера (лимиты, затем ~20 мин недоступности DNS `api.z.ai`) держал не больше трёх.
- `/wrush` заменён на `/rush` + ручная изоляция, когда пользователь попросил `/rush`; worktree оставлен, потому что 4 из 5 работ правили один крейт и ломали бы друг другу сборку.
- Коммиты **не делались** — по CLAUDE.md требуется явная просьба. Вся работа (46 файлов) живёт в рабочем дереве.
- HMAC-вариант для #10 отклонён: ключ доставлялся через переменную окружения, а хук исполняется внутри гостя — любой доступный хуку секрет доступен гостю. Принято решение с случайным именем + DACL.
- #33 переоценена мной как churn, но затем всё же сделана (цель требовала закрыть все таски); разделение по типам возврата сохранено — угадывать «безопасное» значение для `BOOL`/`HRESULT`/`SOCKET` запрещено.

## Lessons worth carrying forward

- `cargo build` **не** компилирует код под `#[cfg(test)]`. Зелёная сборка ничего не говорит о тестах — на этом обожглись четыре прогона, один сдал тест с семью ошибками типов.
- `cargo` трижды за сессию держал устаревший тестовый бинарь (`include_str!`, счётчики тестов). При расхождении — `touch` и перепроверка, а не списывание на feature unification.
- Конфликт слияния нужно смотреть глазами: правило «взять обе стороны» годится для тестовых модулей и ломает продукционный код.
- `git status | wc -l` считает **файлы**, а не содержимое: правка внутри уже изменённого файла невидима.
- Однострочный греп по многострочному Rust систематически занижает счёт вызовов.
