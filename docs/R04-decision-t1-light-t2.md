# R04 — решение по модели угроз: T1 + лёгкий T2

Дата: 2026-09-23. Продолжение [R04-external-brokers-ui-isolation.md](R04-external-brokers-ui-isolation.md)
и [общего аудита XA](review-xa-2026-09-20.md). Документ фиксирует обсуждение с
пользователем, принятые решения и запрошенную работу. Реализация по пунктам ниже
ещё не начата — ждёт ответов на открытые вопросы (см. конец).

## Исходное состояние

- Все находки общего аудита (S02–S11, C01–C04, R01–R03, R05, PERF-*) закрыты.
- Конкретные hook-level находки R04 **F1–F6** реализованы и слиты:
  - F1 — окно `anti_rec` закрывается до вызова callback-capable оригиналов
    (ShellExecute*, CoCreateInstance*, SendMessage*).
  - F2 — ShellExecuteEx классифицирует `fMask` (IDLIST / CLASSNAME / CLASSKEY /
    INVOKEIDLIST / DOENVSUBST).
  - F3 — классификатор HWND: `NoTarget` / `SpecialDest` / `Unknown` /
    `OwnSandbox` / `Foreign`; unknown и special больше не разрешаются молча.
  - F4 — установка guards делится на обязательные (com / service / shell →
    отказ запуска) и деградирующие (ui / WinRT → сигнал degraded-init).
  - F5 — SCM/service access-mask: запрет по конкретным опасным битам вместо
    агрегатов `*_ALL_ACCESS`; нормализация `GENERIC_*`, `MAXIMUM_ALLOWED`
    запрещён сразу. Остаток: ANSI-входы `OpenSCManagerA`/`OpenServiceA` не
    перехвачены.
  - F6 — DACL policy pipe: клиентский ACE без `FILE_CREATE_PIPE_INSTANCE`.
- Открытым оставался только **#77 R04** — выбор архитектурного backend-варианта.

## Суть R04 простыми словами

Песочница — это DLL внутри процессов агента, которая перехватывает опасные вызовы
(«охранник внутри комнаты»). Но в Windows много **посредников (brokers)** —
процессов вне песочницы, выполняющих действия по просьбе: Explorer (ShellExecute),
WMI, Планировщик задач, службы (SCM), COM-серверы, терминал, IDE, ssh-agent,
локальные HTTP-серверы. Агенту не нужно действовать самому — достаточно
попросить посредника через pipe / COM / сокет.

Почему хуки это до конца не закрывают:
1. Для Windows агент — это сам пользователь (тот же токен); посредник того же
   пользователя выполняет «свой» запрос.
2. Хуки — denylist: неизвестный посредник с произвольным именем проходит.
3. Охранник в той же комнате: злонамеренный native-код может обойти DLL
   (прямой syscall, снятие хука, отсутствие DLL).

## Модели угроз

| Модель | Пример | Хватает ли хуков |
|---|---|---|
| T1 — ошибающийся агент | удаляет файлы, force-push, запускает установщик; обходить нас не пытается | да, особенно после F1–F6 |
| T2 — враждебный код | вредоносная зависимость / build script, целенаправленно ищущий обход | нет, нужна граница на уровне ОС |

## Рассмотренные варианты backend

- **A** — исправление хуков. Сделано (F1–F6).
- **B** — UI-ограничения Job Object (8 флагов ядра). Дёшево; закрывает часть UI,
  но не pipes / COM / службы / сокеты. Для T2 не решение.
- **C** — отдельная window station + desktop + restricted token. Средне-дорого,
  сложная модель ACL.
- **D** — AppContainer/LPAC + собственный broker + вынос UI (ConPTY). Реальная
  граница для T2; ~3–5 инженеро-месяцев; прозрачный CoW overlay внутри
  AppContainer не работает сам по себе; совместимость toolchain нужно проверить
  (LPAC-spike). Рекомендация консультанта ox.
- **E** — отдельный пользователь Windows. Не полное закрытие, нужна админская
  настройка.
- **F** — VM / Windows Sandbox. Самая сильная изоляция, самый тяжёлый UX.

Ключевой инсайт ox: UI-флаги Job выключены из-за того, что `wezterm-gui` в режиме
`winrsbox shell` живёт внутри песочницы. Вынос терминала наружу (ConPTY) снял бы
конфликт «безопасность против IME / раскладки / вставки». Живым тестом не
подтверждено.

## Решение пользователя

> Это T1, но если легко делается что-то из T2, то обязательно делаем.

- Целевая модель: **T1 + лёгкий T2** — всё, что даёт защиту на уровне ядра
  Windows малой ценой.
- D (AppContainer) и F (VM) сейчас **не делаем**; они фиксируются как путь на
  будущее.
- Жёсткое требование: **не сломать консольные Claude Code и Codex, запущенные
  под терминалом.**

## Анализ совместимости с Claude Code / Codex

### Два режима запуска

- **(а) агент из обычного терминала** (`winrsbox -- claude` в Windows Terminal /
  WezTerm). Терминал вне Job, внутри только агент. Раскладка, IME и вставка текста
  обрабатываются терминалом и приходят в агент консольным вводом, без буфера
  обмена — флаги Job это не затрагивают.
- **(б) `winrsbox shell`** — `wezterm-gui` запущен внутри песочницы. Все прошлые
  поломки (поштучный bisect в комментариях `jobctl.rs:73-124`) получены в этом
  режиме.

### Что у консольного агента реально касается UI-объектов Windows

1. Вставка картинки Ctrl+V: Claude Code читает буфер через PowerShell
   `Get-Clipboard`, Codex — напрямую через Win32 clipboard API.
2. Копирование из агента в буфер обмена.
3. Логин через браузер (OAuth, `start` / ShellExecute; DDE-ассоциации требуют
   сообщений чужим окнам).
4. Git Credential Manager — окно, владельцем которого является окно консоли
   (чужой HWND).

### Флаги Job UI в режиме (а)

| Флаг | Что запрещает | Риск для Claude Code / Codex | Решение |
|---|---|---|---|
| HANDLES 0x01 | использование чужих окон | GCM, DDE-логин, OLE-буфер | только `--strict-ui` |
| READCLIPBOARD 0x02 | чтение буфера | ломает вставку картинок | только явно (как сейчас) |
| WRITECLIPBOARD 0x04 | запись в буфер | ломает копирование | только явно |
| SYSTEMPARAMS 0x08 | `SystemParametersInfo(SET)` | агентам не нужен; по bisect мешал вставке | кандидат, измерить |
| DISPLAYSETTINGS 0x10 | смена разрешения | не нужен; по bisect мешал вставке | кандидат, измерить |
| GLOBALATOMS 0x20 | общая таблица атомов | зарегистрированные форматы (PNG) получают другой ID — картинка может не читаться | только `--strict-ui` |
| DESKTOP 0x40 | `CreateDesktop`/`SwitchDesktop` | не нужен; по bisect ломал вставку | кандидат, измерить |
| EXITWINDOWS 0x80 | выход / выключение | не нужен; по bisect ломал `GetClipboardData` | кандидат, измерить |

## Запрошенная работа (план)

### 1. Урезанный токен гостя (лёгкий T2, ядро Windows)

Сейчас корень гостя запускается `CreateProcessW` с полным токеном того, кто
запустил winrsbox; при запуске от администратора (нужен для WFP / ETW) агент тоже
администратор. План: `CreateRestrictedToken` + `CreateProcessAsUserW`
(для урезанной версии собственного токена `SeAssignPrimaryTokenPrivilege` не
требуется); наследуется всеми потомками, работает без DLL.

- Все привилегии, кроме `SeChangeNotify`, снимаются (`DISABLE_MAX_PRIVILEGE`).
  Для не-админского запуска это SeShutdown / SeUndock / SeIncreaseWorkingSet /
  SeTimeZone — CLI-агентам не нужны; фактически no-op.
- При админском запуске:
  - Administrators → deny-only;
  - integrity level понижается High → Medium (иначе остаётся UIPI-преимущество
    над обычными окнами);
  - владельцем новых объектов явно ставится SID пользователя (у админского
    токена владелец по умолчанию — группа Administrators, deny-only SID
    владельцем быть не может → иначе ошибки создания файлов).
- Restricting SIDs **не** добавляются: `IsTokenRestricted` остаётся false, node /
  Electron / Chromium не переключаются в особое «restricted» поведение.
- Нюанс Codex: его собственная Windows-песочница в обычном режиме строит ещё более
  урезанный токен из нашего — допустимо; режим, требующий установки с правами
  администратора, при админском запуске работать перестанет (ожидаемо).

### 2. B — UI-флаги Job

- Флаг `--strict-ui`: все 8 флагов, только явно. Исправить комментарии в
  `jobctl.rs`, обещающие это от `--strict-clipboard` (на деле он включает только
  READ/WRITE CLIPBOARD).
- Автоматическое измерение в режиме (а): для каждого кандидата
  {SYSTEMPARAMS, DISPLAYSETTINGS, DESKTOP, EXITWINDOWS} по отдельности и для
  всей четвёрки — чтение изнутри песочницы текста и картинки, положенных в буфер
  снаружи.
- Если четвёрка не ломает чтение — включить её **по умолчанию везде, кроме
  `winrsbox shell`** (лаунчер знает режим сам; эвристика по TTY не используется).
- Ручная проверка пользователем после этого: Ctrl+V картинки в Claude Code и
  Codex, логин через браузер, IME.

### 3. `OpenSCManagerA` / `OpenServiceA` (T1)

Перехватить ANSI-входы тем же классификатором, что F5 ввёл для W-входов.
Агенты это не используют — риск совместимости нулевой.

## Сознательно не делаем

AppContainer / LPAC, отдельная window station, изоляция pipes / COM / служб на
уровне ОС, VM, вынос терминала наружу (ConPTY-инверсия). Всё это — переход к
вариантам D / F за пределами «лёгкого T2».
